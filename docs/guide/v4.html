OVERVIEW

v4 で達成すること

v3 は Host と MCP を別プロセスにし、Streamable HTTP の /mcp でつないだ。 v4 は同じ Server を backend/modules/backlog-mcp に置き、Host と同じプロセスで動かす。 口は MCP のままである。変わるのはトランスポートだけである。

目的は Backlog 製品を完成させることではない。次の問いに、コードで答えられるようにすることである。

  • Host / Client / Server は、どのプロセスのどのファイルか
  • Client(server) と Client(url) は、Host から見て何が同じか
  • なぜ HTTP の /mcp をやめたか
  • 1 ユーザー 1 スペースは、MCP の tool 引数ではなく Host の約束である理由
観点v3v4
プロセスapi と mcp の二つapi 一つ
Host→MCPClientSession + Streamable HTTPClient(server) または Client(url)
自作 MCP の口/mcp（compose 内部）メモリ。HTTP 口は無い
複数 MCP自作 1 本mcp_servers リスト。id で prefix
スペース1 ユーザーが複数1 ユーザー 1 本。上書き

STEP 1

modules/backlog-mcp はライブラリである

v3 の v3/mcp は自分でポートを待ち受けた。 v4 のパッケージは create_server が MCPServer を返すだけである。 run() も /health も無い。 

# backend/modules/backlog-mcp/src/backlog_mcp/server.py
from mcp.server.mcpserver import MCPServer


def create_server(settings: Settings, api: BacklogApi | None = None) -> MCPServer[None]:
    server = MCPServer(
        name="backlog-mcp",
        instructions="Backlog 課題を、渡されたスペースと token に対して一覧する。",
    )

    @server.tool()
    async def list_issues(space: str, access_token: str, status_id: int | None = None) -> str:
        return await run_list_issues(
            backlog, space=space, access_token=access_token,
            status_id=status_id, count=settings.issue_limit,
        )

    return server

Host は uv の path 依存でこれを読む。 

# backend/pyproject.toml
dependencies = [
  "backlog-mcp",
  # ...
]

[tool.uv.sources]
backlog-mcp = { path = "modules/backlog-mcp", editable = true }

list_issues の引数は v3 と同じである。 space と access_token を要求する。 1 ユーザー 1 スペースは、この関数の約束ではない。

STEP 2

高水準 Client がトランスポートを隠す

v1 / v3 は低水準の ClientSession と streamable_http_client を使った。 initialize の往復をコード上に置くためである。 共通の地図にも「その事実が要らなくなったら Client に移してよい」と書いてある。

v4 で見せたいのはその往復ではない。 自作と外部を、同じ口で束ねることである。 

from mcp import Client

async with Client(server) as client:
    listed = await client.list_tools()

async with Client("http://example.invalid/mcp") as client:
    listed = await client.list_tools()

渡した値の型でトランスポートが決まる。 サーバーオブジェクトなら同一プロセス。 URL 文字列なら Streamable HTTP。 list_tools / call_tool は同じである。

in-process は JSON-RPC のフレームを省略することがある Host から見えるのは MCP の tool 契約である。 バイト列としてのプロトコルを揃えたいわけではない。
STEP 3

McpHub が prefix して束ねる

Host の loop は McpHub だけを見る。 どのサーバーがメモリで、どれが HTTP かは、接続を開く 1 箇所だけが知る。

LLM に渡す tool 名は {id}_{元の名前} である。 例は backlog_list_issues。 id は ^[a-z][a-z0-9]{0,31}$ で、underscore を入れない。 振り分けは最長一致である。 

[
  {"id": "backlog", "kind": "inprocess"},
  {"id": "docs", "kind": "http", "url": "https://example.invalid/mcp"}
]

環境変数は MCP_SERVERS。 既定は backlog の inprocess 1 本である。 kind=inprocess の id は、Host の create_inprocess_server に無いと ValueError になる。 v4 が知っている id は backlog だけである。

schema から space と access_token を除くのも Hub である。 LLM が付けてきた token は捨てる。

STEP 4

1 ユーザー 1 スペースは Host の約束

v3 は 1 ユーザーが複数スペースを持てた。 LLM は list_connected_spaces で候補を見し、space を選んだ。 v4 はその選択を Host に移す。 学びを「複数 MCP の束ね方」に寄せるためである。

store のキーは user_id である。 同じユーザーの 2 本目の OAuth は、旧行を置き換える。 切断 API は無い。

未接続なら tool 結果は「接続ボタンから」である。 refresh 失敗なら「接続し直してください」である。 どちらにも URL は付けない。

STEP 5

接続はチャットの外。2 本目は上書き

OAuth は「課題を教えて」の途中では始まらない。 流れは v3 と同じである。callback が書く先が、その user の 1 行になる。

sequenceDiagram participant User participant FE as frontend participant Host as backend_api participant Backlog User->>FE: Backlog を接続 FE->>Host: GET /backlog/connect?user_id&org_id User->>Host: スペースを入力 Host->>Backlog: 302 OAuth2AccessRequest User->>Backlog: 同意 Backlog->>Host: GET /backlog/callback?code Host->>Backlog: code を token に交換 Host->>Host: connections に user の 1 行を上書き Host->>FE: 302 ?connected=1

Backlog アプリの Redirect URI は http://localhost:8004/backlog/callback である。 v3 の 8003 とは別なので、Developer サイトにこの URI を足す。

STEP 6

検証用フロント

検証 UI は v3 と同じく Compose に載せない。 VITE_API_BASE_URL は http://localhost:8004。 vite の port は 5174 である。 

cd v4 && docker compose up
cd v4/frontend && pnpm install && pnpm dev

接続リンクの文言は「Backlog を接続（既存があれば上書き）」である。

WRAP UP

到達点を確かめる

  • v4/compose.yaml に mcp サービスが無い
  • ClientSession / streamable_http_client / MCP_SERVER_URL が v4/backend に無い
  • LLM に渡る tool 名が backlog_list_issues である
  • 同じ user で 2 スペース OAuth すると、store は後者だけである
  • cd v4/backend && uv run pytest が緑である

ここまで追えれば、同一プロセスでも口は MCP であり、 外部 MCP を足すときは mcp_servers に URL を 1 行足せばよい、と説明できる。

別プロセスの HTTP 常駐は v3 学習書 に残してある。 対比して読む。
